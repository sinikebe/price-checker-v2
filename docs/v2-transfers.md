# Quota OFF et transfert inter-instances V2

En fonctionnement normal, les requêtes Open Food Facts partent du **backend** V2. Le navigateur appelle `/api/v2/products/off/*` ou l'action de rafraîchissement d'une fiche. Si le quota serveur est épuisé, une lecture directe de fiche par code-barres peut être effectuée dans le navigateur pour un aperçu temporaire seulement : elle ne renseigne pas la base, ne contourne pas le quota serveur et dépend du CORS OFF. La recherche texte ne permet pas cette lecture intégrée à cause du CORS de Search-a-licious ; un lien vers sa page Web est proposé. Le rafraîchissement serveur demandé est inscrit dans une file durable et repris automatiquement après retour de capacité. Chaque requête sortante (recherche, code-barres, fiche complète, redirection éventuelle) passe par le transport HTTP commun. La migration `0010_shared_off_quota` enregistre les admissions dans PostgreSQL sous un verrou transactionnel, en fenêtre glissante stricte de 60 secondes : **15 lectures de produit** et **10 recherches** au maximum, tous comptes et processus backend de la même base confondus. Une requête excédentaire reçoit 429 avec `Retry-After` quand le délai est calculable. Si la base ou le registre ne répond pas, aucune requête OFF non comptabilisée ne part (503). Le cache serveur évite de dépenser des admissions pour les réponses encore valides. Les limites OFF peuvent aussi s'appliquer à d'autres applications partageant la même IP ; leur 429 reste respecté. Des instances ayant des bases différentes ne partagent pas ce compteur et doivent être configurées séparément si elles partagent une IP sortante.

Dans **Paramètres → Transférer produits et prix**, un administrateur peut télécharger un JSON versionné puis l'importer dans une autre instance V2. L'archive contient les instantanés des **produits publiés** (y compris leurs versions précédentes), les enseignes et points de vente référencés, et les **observations de prix publiées non remplacées/non contestées** avec prix, date, canal, disponibilité et note. Elle exclut les comptes, sessions, brouillons de produits et de prix, recettes, paniers, offres brutes, journaux d'audit, captures et fiches OFF complètes. Les prix transférés sont identifiés sur la destination comme provenant d'une autre instance Price Checker (`third_party`), pas comme des saisies locales approuvées par son admin.

L'import vérifie le format et les références, puis applique le lot dans **une transaction**. L'identifiant stable de l'instance source et les identifiants source rendent un réimport identique idempotent ; de nouveaux produits ou prix source peuvent être ajoutés par un export ultérieur. Un EAN déjà présent dans le catalogue courant cible, un produit source modifié après un précédent import ou une archive invalide bloque le lot entier avec 409/422, sans écraser les données locales. Il s'agit d'un **transfert ponctuel, pas d'une synchronisation** : un relevé retiré ou contesté après l'export n'est pas supprimé automatiquement sur la destination. Exporter/importer uniquement depuis des instances V2 de confiance. Limite du transfert Web : 24 Mio par archive.
